# Управление контекстом

Задание прямо запрещает «отправлять целые веб-страницы в контекст AI». В webpilot это
решается на четырёх уровнях: восприятие, представление, история и субагенты.

## 1. Восприятие: снапшот вместо HTML

`browser/dom_snapshot.js` обходит DOM (включая открытые shadow root'ы и same-origin iframe) и
возвращает **только то, что можно адресовать**:

* интерактивные элементы (`a[href]`, `button`, `input`, `select`, `textarea`, `summary`,
  `label[for]`, `[role]`, `[contenteditable]`, `[onclick]`, `[tabindex]`, `cursor:pointer`) —
  с ролью, доступным именем, состоянием и **числовым id** (`data-webpilot-id`), которым
  агент затем адресует действие;
* текст страницы блоками с их видом (заголовок/параграф/таблица/алерт), без `script`/`style`;
* алерты и текст блокирующих диалогов, позиция скролла, вкладки, ошибки консоли.

Замеры на реальных страницах (`scripts/measure_perception.py`): снапшот в 16–56 раз дешевле
сырого HTML, см. `docs/RESEARCH.md`.

## 2. Представление: жёсткий бюджет и дельта-режимы

`browser/snapshot.py::render_page_model(model, budget_tokens, mode)` собирает текстовый блок
в порядке полезности (алерты → интерактивные элементы во вьюпорте → элементы вне вьюпорта →
текст) и **гарантированно не превышает бюджет**: сначала оценка построчно, затем бинарная
обрезка. Потери честно отражаются в модели (`truncated`, `dropped_elements`,
`text_dropped_chars`), поэтому по счётчикам всегда видно, что именно не попало в контекст.

Три режима:

| режим | что попадает в контекст |
|---|---|
| `full` | все элементы + ранжированный текст (первый взгляд на страницу) |
| `delta` | только изменившиеся элементы + строка «(unchanged: N)» |
| `text` | только текст (используется субагентом-экстрактором) |

## 3. История: окно, свёртка, скрэтчпад

`agent/memory.py::ContextManager` держит разговор в бюджете `context_token_budget`:

1. **Скользящее окно** — последние `history_window` шагов в контексте дословно.
2. **Свёртка** — более старые шаги сворачиваются в «эпизодический конспект»
   (`Summarizer`, а без модели — детерминированный список пунктов), счётчик `compactions`.
3. **Динамический бюджет страницы** — при заполнении истории бюджет страницы ужимается от
   `page_token_budget` до `page_token_budget_min`; свежее наблюдение при этом никогда не
   теряется (оно пере-рендерится или заменяется строкой `page unchanged since step N`).
4. **Скрэтчпад `notes`** — заметки, которые агент ведёт сам и которые включаются в каждый
   запрос, поэтому переживают любую свёртку.
5. **Обрезка результатов инструментов** до `max_tool_result_tokens`.
6. **Дедупликация состояний** — тот же хеш страницы не переотправляется.
7. **Защита от циклов** — одинаковый вызов инструмента с тем же состоянием страницы
   `loop_detection_repeats` раз подряд → в контекст попадает жёсткое предупреждение.
8. **Учёт по факту** — `Usage` из ответа провайдера складывается по шагам; `count_tokens`
   (tiktoken-эвристика, `tokenizer.py`) используется для решений *до* отправки запроса.

Структурная часть (`build_messages`) гарантирует, что итоговый список сообщений не превышает
бюджет: удаляются целые группы шагов (сообщение с `tool_result` никогда не остаётся без
своего запроса). Это закреплено стресс-тестом на 200 синтетических шагов
(`tests/test_memory.py`).

## 4. Субагенты: изоляция вместо раздувания

Большие объёмы текста никогда не попадают в основной контекст:

* **extractor** (`ask_page`) читает «сырой» текст/HTML страницы в *своём* контексте
  (бюджет `extractor_token_budget`), возвращает только ответ + цитату-доказательство и
  уверенность;
* **recovery** получает компактные дайджесты шагов и ошибку, возвращает совет и до трёх
  альтернативных вызовов;
* **summarizer** сворачивает историю.

Все они возвращают свой `Usage`, поэтому в транскрипте видно, сколько токенов ушло на
основной цикл, а сколько — на субагентов (`RunResult.usage.main` / `.subagents`).

## 5. Наблюдаемость

Каждый шаг пишется в транскрипт `~/.webpilot/transcripts/run-*.jsonl`: вызов инструмента с
аргументами, результат, риск, изменения страницы, длительность, токены запроса/ответа.
CLI показывает `θ context steps=…, history_tokens=…, page_tokens=…, compactions=…,
dropped_items=…` после каждого шага, так что видно, как контекст-менеджер дышит во время
работы — это удобно и для отладки, и для демонстрации.
